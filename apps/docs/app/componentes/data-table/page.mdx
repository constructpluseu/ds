# Data Table <StatusBadge status="disponivel" />

Tabela densa com ordenação por coluna e seleção de linhas, para listar conjuntos de dados como obras, orçamentos ou faturas.

## Quando usar

- Para listar registos com várias propriedades comparáveis lado a lado (obra, cliente, orçamento, estado).
- Quando o utilizador precisa de ordenar por uma coluna ou selecionar várias linhas para uma ação em lote (ex.: exportar, arquivar).

## Quando não usar

- Para uma lista simples de itens sem colunas comparáveis — use `List` ou `Structured List`.
- Para grelhas muito grandes que precisem de paginação, filtros avançados ou colunas fixas ao deslocar — este componente não inclui paginação nem "virtualização"; combine com `Pagination` e pagine os `rows` fora do componente.

## Anatomia

Tabela HTML nativa com cabeçalho (coluna de seleção opcional + colunas de dados, algumas ordenáveis) e corpo com uma linha por registo, cada uma com checkbox de seleção opcional.

## Tamanhos

Não expõe variantes de tamanho — a densidade da tabela é fixa; ajuste `--cp-space-*` no CSS partilhado se precisar de uma variante mais compacta no futuro.

## Estados

| Estado | Comportamento |
|---|---|
| Sem linhas | Mostra `emptyMessage` numa linha que ocupa todas as colunas. |
| Coluna ordenada | Cabeçalho com seta preenchida e `aria-sort` correspondente. |
| Linha selecionada | Fundo destacado com a cor de acento. |
| Checkbox de cabeçalho parcialmente selecionado | Estado indeterminado quando só algumas linhas visíveis estão selecionadas. |

## Comportamento

- **Componente controlado**: o `Data Table` não ordena nem filtra os dados sozinho — recebe `sortKey`/`sortDirection` e devolve, via `onSortChange`, a **próxima** direção sugerida (`"asc"` → `"desc"` → `null`, cíclico); a aplicação aplica essa ordenação aos `rows` antes de os passar de novo ao componente. O mesmo vale para a seleção: `selectedKeys`/`onSelectionChange` são geridos pela aplicação.
- Clicar no cabeçalho de uma coluna ordenável (ou no botão que o compõe) avança o ciclo de ordenação; colunas sem `sortable` não são clicáveis.
- O checkbox do cabeçalho seleciona/limpa todas as linhas atualmente passadas em `rows` (não apenas as visíveis num ecrã, caso a aplicação implemente paginação por fora).
- Em React, a prop opcional `renderCell(row, column)` permite formatar o conteúdo de qualquer célula (ex.: moeda, datas, badges) sem alterar os dados em `rows`. Vue e Angular não têm equivalente direto a esta prop nesta versão — formate o valor antes de o colocar em `rows` nesses frameworks.

## Conteúdo

- Cabeçalhos de coluna curtos e concretos: **&ldquo;Orçamento&rdquo;**, não **&ldquo;Valor associado ao registo&rdquo;**.
- `emptyMessage` deve nomear o que falta: **&ldquo;Sem obras registadas.&rdquo;**, não um genérico **&ldquo;Sem dados.&rdquo;**, sempre que o contexto permitir ser específico.

## Acessibilidade

- Usa elementos `<table>`/`<thead>`/`<tbody>`/`<th scope="col">` nativos — a estrutura tabular é anunciada corretamente por leitores de ecrã sem papéis ARIA adicionais.
- A coluna atualmente ordenada declara `aria-sort="ascending"`/`"descending"` no `<th>`; as restantes colunas não declaram `aria-sort` (equivalente a `"none"`).
- Um `caption` (visualmente oculto via `cp-visually-hidden`) descreve o conteúdo da tabela para quem navega por leitor de ecrã.
- Cada checkbox de seleção tem `aria-label` explícito (ex.: "Selecionar linha 2"; cabeçalho: "Selecionar todas as linhas").

## Relacionados

- **Pagination** — combine com `Data Table` para dividir grandes conjuntos de dados em páginas.
- **Structured List** — alternativa mais leve para listas sem necessidade de ordenação ou seleção.
- **Checkbox** — a coluna de seleção reutiliza o mesmo estilo visual do `Checkbox`.
